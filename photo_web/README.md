# photo_web｜材料自主檢查照片產生器

上傳施工查驗照片（或任何照片），依 photo-inspection-log Skill 規則產出公司格式「材料自主檢查照片.xlsx」。
網頁只負責收件、呼叫、確認、交件；排版與名詞只由 Skill 的既有腳本與範本決定，腳本在執行時從
icashkin-cmyk/miko 固定 commit（`pipeline.SKILL_COMMIT`）下載，不在本 repo 複製一份。

## 流程（三步；對應 SKILL.md「二、流程」）
1. 上傳照片（20 張以內或 zip；可附上次的 xlsx 接續）→ `preflight start`、`restore`、`prep`（SHA-256 去重）→ 自動讀字成草稿。
   - 想要更準（選用，不用金鑰）：第 1 步的折疊區有一段可複製的話（`reader.IMPORT_PROMPT`），把同一批照片和這段話丟給 Claude 等 AI 對話，
     把回覆的 JSON 貼回來（或上傳 .json）。`reader.parse_import` 檢查格式（只收認得的欄位、型別不對拒收、整份上限 1 MB、最多 200 筆、每張組成草稿後上限 4000 字，工程資料、項目、位置、人員、日期、建議項目每欄上限 200 字，單行欄位與每一行裡的換行、定位改成空白並去掉頭尾空白（中間的空白原樣）、控制字元去掉、含不成對代理字元拒收、鍵只取檔名〔/ 與 \ 都切〕；
     取 JSON 只用字串切割：整段、``` 程式碼區塊、第一個 { 到最後一個 } 依序試，不用會回溯的正規表示式），
     `ImportedReader` 依原檔名或 SHA-256 對到照片當草稿；沒對到的照片用本機 OCR，並在該張標明。內容只當成抄寫文字，仍要在確認頁看過。
     讀圖建議的檢查項目（`suggest_item`，不在草稿文字裡）在確認頁該張下方顯示成可改、可清空的欄位，按產出當下把這一格的值與選的材料表品項記在工作上（`Job.confirmed_sug`、`Job.chosen_forms`），產出只用記下的值；部分照片寫入失敗後重試也不會掉。
     照片是使用者自己交給 AI 對話的（折疊區有提醒先確認可以外傳），網頁本身不送外部服務。
     含外來文字（讀圖檔、自動讀到的字、檔名）的提示訊息一律用 `app.say`（`html.escape` 後以 `st.html` 顯示，不經 Markdown，連續空白照樣顯示），只顯示成字，不會變成圖片、連結、粗體或表情符號。
     測試工具（Playwright）用含中文的磁碟路徑選檔會失敗；網頁本身收得下中文檔名（獨立稽核以記憶體內容上傳驗證）。
2. 確認內容（一頁）：
   - 工程資料（工程名稱、監造單位、承造單位）整批確認一次：預設取各張讀到的多數寫法，沒讀清楚（含〔?〕）的寫法不當預設；
     各張寫法不同時列出來讓使用者確認上面那一個。確認值只寫進「這張照片上讀得到該欄」的照片；人工抄寫時每張都用。
     （Skill 的規則是固定欄位與基準不同就不寫並問使用者；網頁把「問」集中成這一次確認，按「產出 Excel」即視為確認並寫入基準。）
     整批沒有任何一張讀到的欄位，使用者自己補填的值每張都寫入（不知道就留空）。
   - 可能是別的工程的照片：某張讀到的工程資料和確認值相似度低於 0.5（`pipeline.MISMATCH_RATIO`；只差幾個字的讀錯字不算）時，
     頁面用紅字指出是第幾張，使用者要逐張選「不放這一張」或勾「是同一個工程（只是讀錯字）」；沒選不能產出，「全選」不會代選。
   - 全名相似度夠、但兩邊都讀到完整後綴（建築師事務所、營造有限公司等）且去掉後綴後完全對不上的，也會被指出；後綴讀錯或有〔?〕時只比全名，避免誤報。
     改了上面的工程資料或拿掉照片造成工程資料變動時，先前勾的「是同一個工程」全部失效，要重新勾。
   - 拿掉照片後，工程資料三欄依剩下的照片重新帶入（被拿掉那張的值不留），頁面會提醒再確認一次。
   - 每張照片都有「不放這一張」（只剩一張時沒有；要整批重來請按「結束並刪除暫存」）。
   - 每張照片一個文字框（工作檔格式）與「我看過這一張了」；可用「全選」。有任何一張沒打勾就不產出。
   - 按「產出 Excel」：`addmany` → `base --all` → `make_entries` → `build_company` → 公式改回文字 → `preflight deliver`
     （照片或使用者的字以「=」開頭時，`build_company.py` 會寫成 Excel 公式；網頁在產出後把所有公式格改回文字、字不動。公司範本的產出檔本來沒有公式。）
     （印 FAIL 也回 0 的既有缺陷由本模組攔下）。有照片寫不進去時說明原因、留在這一頁。
   - 字數上限以字數算（罕用字與表情符號算 1 個字）：每張文字框 4000 字（`pipeline.MAX_TEXT`），工程資料、建議的檢查項目與下載頁的單行欄位 200 字（`pipeline.FIELD_MAX`）；內容本來就比較長時，上限取當時的長度。上限在這一批第一次顯示時定下，之後不跟著輸入的值變（`Job.limit`；Streamlit 一換 `max_chars` 就會把輸入框清空）。輸入框本身放寬到兩倍（瀏覽器把罕用字算 2 個），超過字數上限時按產出會擋下並說明是哪一格、上限與目前字數，不靜默截斷（`pipeline.check_len`）。
   - 「產出 Excel」「重新產出 Excel」按下後這一輪按鈕不能再按；整段流程在 `Job.produce` 裡一次跑完（中間不讀寫畫面狀態，連按兩下的第二下中斷不了），同一個工作一次只跑一輪（`Job.working`），結果先記在工作上再搬到畫面。被擋下的原因顯示在按鈕上方，按鈕恢復可按。已按下產出或產出進行中再按「不放這一張」不會生效（`Job.drop_if_idle`），畫面會說明那一張仍在 Excel 裡與怎麼拿掉；確認頁的提示不會留到下一批。寫檔前另有一道 30000 字的檢查（`pipeline.CELL_MAX`），超過就不產出並說明是第幾張；產出後再檢查每一格，任何一格到達 Excel 一格 32767 字的上限（內容會被截斷）就不交檔並說明是哪一格。
   - 〔?N〕的 N 超過 3 位數（含全形數字）時擋下並請使用者改成〔?〕；同一張最大編號加上沒編號的〔?〕個數超過 999 時也在寫入前擋下（`pipeline.check_x`、`check_q_total`；Skill 會從最大編號往下編，N 很長會把一格撐到幾萬字）。不靜默改。
   - 「_x0041_」這種字樣（底線、x、四位十六進位、底線）Excel 檔案格式會解碼成別的字；「x005F_」openpyxl 讀檔時會整段刪掉。寫進去會和畫面不同：讀圖檔、照片文字、工程資料、建議項目、修改欄位與檔名裡出現時，寫入前擋下並說明（`pipeline.check_x`；先去掉控制字元與全形括號註記再查）。
     產出後另直接看 xlsx 裡的 XML（`Job.check_output`），還有這種字樣（例如 Skill 處理後才拼出來的）就不交檔。
   - 文字寫入之後才失敗（產生 entries、產出、交檔檢查、上面這一道）時，確認頁已經改不了：訊息會明講要按左側「結束並刪除暫存」重新上傳（`pipeline.STUCK`）。
   - 看不見的控制字元（含 U+0085、U+2028、U+2029 三種特殊換行）寫檔時去掉；工程資料與建議項目只把換行、定位變成空白並去掉頭尾空白，中間的空白原樣。
   - 檔名（含 zip 裡的）有控制字元、換行或定位字元、或超過 200 位元組（中文約 60 字）時，收件就擋下並請使用者改檔名（`Job.check_names`）。
   - 可見分頁的排版照 Skill 的 `build_company.py`：同一行裡重複的欄、「—」會省略，行首行尾空白會去掉；原文完整留在隱藏的「原文」分頁。這是 Skill 的規則，網頁不改，下載頁有說明。
   - 材料表品項（選用）：每張照片可從 Skill 內建材料表（`forms.csv`）選一個品項，比較像這張讀到的字的排前面。選了以後檢查項目用材料表的
     材料/設備名稱、設計/標準值用「工作表名稱＋品質管理標準」（與 `make_entries` 對到材料表時的寫法相同）；勾「實測值與材料表相符」時實測值同寫，
     原本只在實測欄的內容（白板實測、量測讀數）接在後面不覆蓋。
     只改 entries，不改原文。這是為了不靠讀字：實測（9 張、97 詞）用材料表名詞校正讀錯字 44/97、放大 2 倍 51/97，與基線 45～46/97 沒有明顯差別。
     限制：選擇不會存進 Excel；下次接續（上傳這次的 xlsx）時，舊照片回到讀字的內容，要用「修改欄位」重填。下載頁有寫明。
3. 下載：Excel；要改分項工程名稱、檢查項目、設計/標準值、實測值、棟別時，用「修改欄位後重新產出」（選用）。

## 讀字方式（`reader.make_reader()`，依序）
- `PHOTO_FIXTURE=<answers.json>`：固定答案（驗收用，依照片 SHA-256 對應）
- `ANTHROPIC_API_KEY`（平台密鑰設定，不寫進檔案）：Claude API 視覺讀圖。**尚未實跑（NOT_RUN），費用待決定**。
  只有同時設了 `PHOTO_ALLOWED_EMAILS` 與 `PHOTO_DAILY_LIMIT` 才會啟用；沒同時設時改用下面的自動讀字。一張讀圖失敗只影響那一張，改人工抄寫。
- 預設：本機 OCR 自動讀字（`ocr_reader.py`，RapidOCR 的 PP-OCRv6 small 模型），不用金鑰、照片不送到外部服務。
  模型在第一次使用時由 RapidOCR 從它的模型站下載並快取。
- OCR 不能用（沒裝、模型下載失敗、`PHOTO_OCR=0`）：人工抄寫。

### 自動讀字的做法與限制
- 找印刷標籤（工程名稱、監造單位、承攬廠商、查驗項目、檢查人員、查驗日期、廠牌）取值；白板斜拍時先扶正再分列；最右邊的數字當數量欄。
- 信心低於 0.90 的格子後面加〔?〕；低於 0.50 的只留〔?〕、不留猜的字。簡體字形轉繁體（`ocr_reader.to_trad`）：只轉「只會是簡體」的字
  （cp950 沒收、而且本身不是繁體字形的字，例 这、规、进、个、灯；加上 `FORCE` 的 厂机体万与网气；啓、峯、裏、恒、温 這類臺灣也在用的字不動），逐字對位；繁體也在用的字一律不動（范、余、于、里、后、斗、杰、制、台、污、游…），
  人名、地名、材料表用字不會被改寫。代價是簡體詞裡這類字會留著（规范→規范、这里→這里、后面→后面、配电柜→配電柜、建筑→建筑），請在確認頁改。
- 白板以外的字（紙箱印刷等）收成一行「（旁註：白板以外的字：…）」；不是白板的照片只照抄看得到的字，不套欄位。
- 查驗日期讀出來不像日期、或和照片日期浮水印不同時只標〔?〕，不改寫。
- OCR 不會描述照片內容（意象）、不會讀量具刻度、不會推定檢查項目：這些欄位留空，由使用者補。
- 實測（2026-11-23，9 張手寫白板，以人工判讀為準）：詞命中 44/97（45%），每張約 1 秒；印刷標籤大多正確，手寫字常讀錯，
  且有信心高但讀錯的字（例：把數量讀成別的數字）。所以草稿一定要人看過；直接全選時，〔?〕會留在 Excel（以〔?1〕〔?2〕這樣的編號標出，可見分頁不是紅字），
  沒被標記的錯字不會被發現。

讀字結果只是草稿，放在記憶體；使用者在第 2 步打勾後才寫入。

## 環境變數
| 名稱 | 用途 | 預設 |
|---|---|---|
| `ANTHROPIC_API_KEY` | Claude API 讀圖的金鑰，只填在平台密鑰設定 | 無（用本機 OCR 自動讀字） |
| `PHOTO_OCR` | 設成 `0` 關掉本機 OCR（改人工抄寫） | `1` |
| `PHOTO_READER_MODEL` | 讀圖模型 | `claude-opus-5-5` |
| `PHOTO_ALLOWED_EMAILS` | 可使用的 email，逗號分隔；設了就要先登入。有設但內容是空的＝沒有人可用 | 無（不限、不需登入） |
| `PHOTO_DAILY_LIMIT` | 每人每日張數上限（zip 裡的也算） | 0（不限） |
| `PHOTO_SKILL_DIR` | 改用本機的 Skill 腳本資料夾（開發用） | 無（從 GitHub 固定 commit 下載） |
| `PHOTO_FIXTURE` | 固定讀圖答案（驗收用） | 無 |

## 限制
- 一次 20 張以內（`pipeline.MAX_PHOTOS`，zip 裡的也算，篩選條件與 Skill 的 `prep` 相同）、解開後總大小 300MB 以內、單張 8000 萬像素以內；巢狀 zip 不處理；副檔名是圖片但內容打不開的檔會在收件時擋下。
- 同名檔案會互相覆蓋，上傳前請確認檔名不同。
- 接續上次的 xlsx 時，照片與原文會帶回來；用「修改欄位後重新產出」改過的欄位（含讀圖建議的檢查項目）不會帶回，要再改一次。
- 每日上限：收件失敗或重複的照片不算；`PHOTO_DAILY_LIMIT` 不是數字或是負數時頁面會顯示設定錯誤。未預期的錯誤細節只寫在伺服器紀錄。
- PDF 預覽需要環境裝有 LibreOffice；雲端沒有新細明體、標楷體時，PDF 的欄寬與字型和電腦版 Excel 不同，只供抽看。
- 每日用量先預扣、收件與讀圖完成後結清：預扣記在工作資料夾（`reserve.json`），處理中被中斷（重新整理、斷線、讀圖中更換檔案）時，沒用到的張數在下一次開啟頁面時退回；已送去付費讀圖（Claude API）的張數照算、不退，避免反覆中斷不占額度地花讀圖費用。結清後按「結束並刪除暫存」不退。
- 每日用量記在暫存資料夾，容器重啟會歸零；沒登入的人以工作階段計，重新整理或換瀏覽器就重算，所以只設每日上限、不設使用者名單時，上限擋不住人；要控管費用請設使用者名單。舊日期的用量（含 email）在隔天起有人開啟網頁時清除；工作資料夾裡的預扣紀錄也含 email，隨資料夾清除。
- 沒設每日上限時也會留一筆不含使用者的「處理中」紀錄，處理中斷的工作資料夾（含照片）在下一次有人開啟網頁時清掉。
- Claude API 讀圖每張逾時 120 秒、重試 1 次，仍失敗就改人工抄寫。
- 已知限制：第 2 步照片還在載入時版面會位移，請等照片顯示完再勾選；自動讀字要另外占約 300MB 記憶體【推論，未量測】；沒有全站的工作數與磁碟總量上限（部署時請調低 `server.maxUploadSize`）。
- 工作資料夾在 `<暫存>/photo_web_jobs/`：按「結束並刪除暫存」立即刪除；沒按時，閒置超過 2 小時後，在下一次有人開啟頁面時清除（沒有人開頁面就不會清；頁面開著並持續操作的工作不會被清）。

## 部署（Streamlit Community Cloud，尚未實際部署）
1. 在 share.streamlit.io 新增 App：repo `icashkin-cmyk/blank-app`、主檔 `photo_web/app.py`、相依檔 `photo_web/requirements.txt`。
2. 需要 PDF 預覽時，在 repo 根目錄加 `packages.txt`（內容 `libreoffice`）。
3. 在 App 的 Secrets 填環境變數（上表）。要限制使用者時再加 Streamlit 的登入設定：
   ```
   [auth]
   redirect_uri = "https://<你的 App 網址>/oauth2callback"
   cookie_secret = "<自己產生的隨機字串>"
   client_id = "<OIDC client id>"
   client_secret = "<OIDC client secret>"
   server_metadata_url = "https://accounts.google.com/.well-known/openid-configuration"
   ```
   金鑰與上列密鑰只填在平台的 Secrets，不寫進 repo。
4. 關掉工具列與錯誤細節：Streamlit Community Cloud 沒有設定畫面，要在 repo 根目錄加 `.streamlit/config.toml`，內容是 `[client]` 區段的 `toolbarMode = "viewer"` 與 `showErrorDetails = "none"`（`false` 仍會顯示堆疊）。本 repo 根目錄的 `.streamlit/config.toml` 目前只有 `[browser]` 的 `gatherUsageStats = false`（關掉 Streamlit 使用統計，瀏覽器才不會連到 Streamlit 的統計主機）；`[client]` 這兩項會同時影響同一個 repo 的其他 Streamlit 頁面，所以沒有加，由部署的人決定。Streamlit 只讀「啟動時所在目錄」的 `.streamlit/`：要從 repo 根目錄啟動，從別的目錄啟動時使用統計不會關。程式啟動時也會把錯誤細節設成 `none`，頁面主體另外包了一層攔截，未預期的錯誤只顯示一般訊息。

```
pip install -r photo_web/requirements.txt
streamlit run photo_web/app.py
PHOTO_SKILL_DIR=<miko>/skills/photo-inspection-log/scripts python3 -m pytest -q photo_web/tests
